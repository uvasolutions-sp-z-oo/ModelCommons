is not a promise that links, versions, licenses, or platform rules remain current
later. Re-check them before every release.

## Android cross-app security

- [AIDL](https://developer.android.com/develop/background-work/services/aidl):
  cross-process calls can arrive concurrently and interfaces require compatible
  evolution.
- [Bound services](https://developer.android.com/develop/background-work/services/bound-services):
  the binder returned by `onBind` is cached, so authorization belongs on every
  entry point.
- [`Binder`](https://developer.android.com/reference/android/os/Binder): capture
  calling UID synchronously before leaving the Binder call/clearing identity.
- [`getPackagesForUid`](https://developer.android.com/reference/android/content/pm/PackageManager#getPackagesForUid(int))
  can return none or multiple packages; shared-UID ambiguity must fail closed
  under the open-ecosystem policy.
- [Parcelable/Bundle limits](https://developer.android.com/guide/components/activities/parcelables-and-bundles)
  and [`IBinder`](https://android.googlesource.com/platform/frameworks/base/+/HEAD/core/java/android/os/IBinder.java):
  the 1 MiB process transaction buffer is shared; ModelCommons adopts a much
  smaller ceiling (48 KiB in the current scaffold, always no more than 64 KiB)
  and 16 KiB event chunks.

## iOS sharing boundary

- [App Groups](https://developer.apple.com/documentation/xcode/configuring-app-groups)
  and the [entitlement](https://developer.apple.com/documentation/BundleResources/Entitlements/com.apple.security.application-groups)
  share a container among apps from the same developer team; they are not a
  general public inference daemon.
- [`containerURL`](https://developer.apple.com/documentation/foundation/filemanager/containerurl(forsecurityapplicationgroupidentifier:))
  is the only supported way to resolve that container; `nil` is a failure.
- [Providing access to directories](https://developer.apple.com/documentation/uikit/providing-access-to-directories)
  describes user-selected open-in-place directories, minimal bookmarks,
  staleness/revocation, coordination, and security-scoped access. The access
  lease must cover the entire mmap/context lifetime.

This permits storage sharing. Unrelated apps still allocate their own runtime,
context, KV cache, DRAM, and accelerator resources.

## Protocol/tool ecosystem

The canonical ModelCommons tool model deliberately separates a model-generated
request from application execution. This leaves room for future Model Context
Protocol integration without making MCP a runtime dependency or allowing model
output to invoke tools directly. Any future bridge must map the then-current MCP
specification explicitly and keep application authorization/confirmation.

- [Model Context Protocol specification](https://modelcontextprotocol.io/specification/)
